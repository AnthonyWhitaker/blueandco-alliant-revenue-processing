# Findings

Bugs and design issues in the existing code found during the migration. On
2026-10-15 the user approved fixing them (rather than reproducing them for
parity). The **Status** column records what has actually been done.

| # | Area | Finding | Evidence | Severity | Status |
|---|---|---|---|---|---|
| F1 | Review | Choosing alias scope **`job_only`** with "Create alias" ticked (the default) creates a **global** alias. | `engine/processor.py` `apply_review_decision` | High | **Fixed** (8d6df01), test `test_job_only_scope_leaves_no_lasting_mapping` |
| F2 | Review | `job_only` decisions were still written to `jde_member_history`, so they carried into future jobs. | same | Medium | **Fixed** (8d6df01) |
| F3 | Infra | One DB connection (`@st.cache_resource`) is shared by all sessions; Azure SQL idle disconnects are never recovered. | `ui/app.py` | Medium | **Fixed in the API** (per-request connection). The legacy app still has it. |
| F4 | Infra | The Dockerfile `HEALTHCHECK` uses `curl`, which the same Dockerfile purges. | `Dockerfile` | Low | **Fixed** (Phase 5): the health check uses Python and probes `/api/health` |
| F5 | Infra | No `.dockerignore`: `COPY . .` can bake `data/revenue.db` / `.env` into the image. | `Dockerfile` | Medium | **Fixed** (Phase 5): `.dockerignore` excludes data, DBs, `.env*`, node_modules and the legacy UI |
| F6 | Infra | Runs as root; base image not pinned; only `:latest` is pushed (no rollback target). | `Dockerfile`, `infra/deploy.sh` | Low | **Fixed** (Phase 5): non-root uid 10001, pinned `python:3.12.15-slim-trixie` / `node:22.22.2-trixie-slim`, images also tagged `:<git sha>`, and the last Streamlit image is kept as `:streamlit-legacy` |
| F7 | Upload | Uploaded files went to `/tmp` and were never cleaned up; `revenue_job.file_path` points at them. | `ui/pages/1_Upload.py` (old) | Medium | **Partly fixed**: files now go to `REVENUE_UPLOAD_DIR` (default `data/uploads`). They are still lost when an Azure revision restarts, because there's no persistent volume. Durable storage is a scope decision. |
| F8 | Tier C | `pivot_allocation` jobs land in `needs_review` with no review items, so they never appear on Review and can't be completed. | `engine/processor.py:508-510` | Medium | **Fixed**: `confirm_job` (`POST /api/jobs/{id}/confirmation`, plus a button on the legacy Export page) |
| F9 | Tier C | `manual_entry` says "a human enters the confirmed total during Upload/Review", but no such input exists. | `engine/processor.py:419-425` | Medium | Open: needs a product decision on where the total is entered |
| F10 | Export | The Payment ID box wrote to the DB on every rerun. | `ui/pages/3_Export.py` (old) | Low | **Fixed**: explicit Save (legacy) / `PATCH /api/jobs/{id}` |
| F11 | Engine | `parse_date_from_filename` was defined twice; the surviving copy returned impossible dates (crashing Upload). | `engine/normalizer.py` | Low | **Fixed** (3175622) |
| F12 | Admin | Member search had three copies with different active/inactive filters. | old UI pages | Low | **Fixed**: one `core.members.search_members(active_only=…)`; each call site keeps its previous filter |
| F13 | Tier C editor | **Confirmed by test:** "Edit existing" never loaded the selected rule's values, and saving after changing only some fields silently reset `sheet_name`, `is_sales_amount` and `sort_order` (e.g. `Summary/1/5` → `None/0/0`). The allocation editor had the same pattern. | `ui/pages/4_Admin.py` (old) | **High**: silently corrupts Tier C config | **Fixed** in legacy (600c291), test `test_tier_c_edit_prefills_and_preserves_fields` |
| F14 | Security | No authentication; public ingress unless `allowedIpRanges` is set; ACR admin user enabled; the SQL admin login is the app's runtime credential. | `infra/` | High for a REST API | Open: **auth decision needed before the first deploy.** `deploy.sh` now refuses public ingress unless `ALLOWED_IP_RANGES` is set or `ALLOW_PUBLIC_INGRESS=true`. |
| F15 | Admin | The Column Map form couldn't map `entity_code_hint` / `account_id_hint` or `contains:` patterns, so Tier A suppliers could only be onboarded by seed script. | old `4_Admin.py` | Medium | **Fixed** (all canonical fields offered; `contains:` documented) |
| F16 | Engine / Azure SQL | **Confirmed on SQL Server 2022:** `_build_review_items` selected un-aggregated columns while grouping by `COALESCE(jde_number, customer_name)` (error 8120), so any job with an unmatched customer failed. The old Review page's job query failed the same way. | `engine/processor.py` `_build_review_items`, old `ui/pages/2_Review.py` | **High**: processing was broken in production | **Fixed** (MIN/MAX aggregates; `core/` Review query is portable). Verified by `make check-mssql` |
| F17 | Engine | Output aggregation groups by raw `process_date`, not earned month, so a PEC gets one output row per distinct date in the same period. The README says "one row per entity code per earned period". Totals are unaffected. | `engine/processor.py` `_aggregate_output` | Unknown: depends on whether Salesforce upload expects one row per PEC × month | Open: needs business confirmation. Current behaviour pinned in `test_pipeline_aggregates_per_pec_and_process_date`. |
| F18 | Engine / Azure SQL | **Confirmed on SQL Server 2022:** `execute_select`'s `LIMIT n` → `TOP n` rewrite found the match in the stripped SQL but sliced the unstripped SQL, cutting characters off the end of any query starting with a newline. Payment ID lookup became `ORDER BY payment_received_d` (error 207), so **every job failed on Azure SQL before reaching matching**. Also hit the Upload page's recent-jobs list and the Review member search. | `engine/db.py` `execute_select` | **High** | **Fixed**, `tests/test_db_dialect.py` + `make check-mssql` |
| F19 | Engine / Azure SQL | **Confirmed:** the upsert → `MERGE` rewrite qualified `occurrence_count` with the table name instead of the `tgt` alias (error 4104). Approving a review item whose JDE was already in history failed; `MemberMatcher.record_jde_match` hit the same error but swallows exceptions, so JDE history counts silently never updated on Azure SQL. | `engine/db.py` `execute_upsert` | **High** | **Fixed**, same tests |
| F20 | Engine / Azure SQL | `LIMIT` on a `SELECT DISTINCT` was rewritten to `SELECT TOP n DISTINCT`, which SQL Server rejects (must be `DISTINCT TOP n`). No current caller hits it. | `engine/db.py` `execute_select` | Low | **Fixed**, `tests/test_db_dialect.py` |
| F21 | Admin › Aliases | The "Supplier-specific" scope can't work inside `st.form`: picking it doesn't rerun, so the Supplier select never appears. On submit the script reruns, renders the Supplier select at its default (the **first supplier alphabetically**) and saves the alias against that supplier without the user ever choosing one. | old `4_Admin.py` alias form | Medium: aliases silently attached to the wrong supplier | **Fixed in the React page** (the supplier select appears live). Legacy left as is. |
| F22 | Admin › Suppliers | "Add / Update Supplier" never pre-fills, and saving upserts by name, so updating one field of an existing supplier (e.g. its contract ID) resets every other form field to the blank form's defaults (header row 0, payor filter cleared, sheet name cleared, job type `row_level`…). Same family as F13. | old `4_Admin.py`, `core.suppliers.upsert_supplier_by_name` | **High**: silently breaks a working supplier's parsing | **Fixed in the React page** (edit opens the saved values; `PUT /suppliers/{id}`). Legacy left as is. |
| F23 | Admin › Members | "Replace all existing members" runs `DELETE FROM member`. Members are referenced by allocation rules, processed rows, review items and JDE history (no cascade), so once any job exists the import fails with a foreign-key error. Before that, it silently deletes every alias (`member_alias` cascades). Even when it succeeds, every member gets a new id. | `engine/member_loader.py:88` | Medium | Open: needs a decision (soft-deactivate missing members instead?). The React page keeps the option but asks for confirmation and says what it does. |
| F24 | Frontend deps | `npm audit` reports two moderate React Router advisories, fixed only in v7.18 ([GHSA-wrjc-x8rr-h8h6](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6) open redirect via a backslash in `<Link>`/`navigate`; [GHSA-337j-9hxr-rhxg](https://github.com/advisories/GHSA-337j-9hxr-rhxg) SSR hydration). The prompt pins React Router v6. | `frontend/package.json` | Low here: every navigation target is an app constant (never user input) and there is no SSR | Open: upgrade to React Router v7 (all v7 future flags are already on, so it should be a small change) |

**Implication of F16/F18/F19:** before this branch, uploading a supplier file could not succeed on Azure SQL at all. If production has been running on Azure SQL, it has not been processing files. Worth checking `revenue_job` there for `failed` rows with these errors, and whether people have been processing locally against SQLite instead.
